# Architecture (living)

Decision record: `docs/DECISIONS.md` ADR-001. Evidence: `docs/research/stack_options.md`.

## 1. Stack (pinned)

| Layer | Choice | Pin |
|---|---|---|
| Language | TypeScript, `strict: true`, no `any` in `packages/sim`. No ESLint in v1: `tsc` + plain-script guards do the enforcing | TypeScript 7.0.x (research found 7.0.2); record in ADR-002 |
| Runtime | Node 22.18+ (Windows 11); env via `--env-file-if-exists=.env` | `engines` field in package.json |
| Monorepo | npm workspaces | no Nx, no Turbo |
| Sim | pure TS, zero DOM and zero three imports | n/a |
| Renderer | three.js **WebGLRenderer** (not WebGPU in v1) | `three@0.186.1` exact |
| Dev server and build | Vite | latest 8.x, lockfile |
| Unit and scenario tests | Vitest | latest 5.x, lockfile |
| Browser automation, screenshots | Playwright + bundled Chromium | `@playwright/test@1.64.0` exact |
| HUD | Preact + @preact/signals, DOM overlay | lockfile |
| Validation | zod schemas for every data file | lockfile |
| Asset tooling | Python 3.11+ in a project `.venv` + Blender 5.2 LTS CLI (via `tools/assets/blender_run.py`) | `tools/assets/requirements.txt` |
| Desktop exe (later) | Electron | backlog |

Never upgrade a pinned package unprompted. To upgrade: read the migration guide, bump in its own commit, run full QA, record an ADR.

Why not WebGPU now: headless WebGPU captures come back blank, and WebGPURenderer drops `onBeforeCompile`, which the curved-world bend uses. WebGPU is a backlog item behind the renderer interface.

## 3. Simulation core (`packages/sim`)

- **Fixed tick 20 Hz.** Data is authored in seconds; the loader converts to ticks. Rendering interpolates between the last two snapshots.
- **Pure step:** `step(state, commands[]) -> state` mutating in place for speed, but the only inputs are the previous state, the external commands for this tick, and the seed. No wall clock, no I/O.
- **Determinism rules** (enforced by `tools/guards/determinism.mjs`, run in `npm run check`):
  - **Math allowlist** in `packages/sim` and `packages/ai`: only `Math.abs, min, max, floor, ceil, round, trunc, sign, sqrt, imul, fround, clz32` (all IEEE exact). Every other `Math.*` and the `**` operator are banned. Trig and other transcendental functions come from `dmath`, whose tables are **generated once and committed as literal numbers** in `packages/sim/src/dmath_tables.ts` (never built at runtime with `Math.sin`, which may differ between the V8 in Node and in Chromium).
  - Also banned: `Math.random`, `Date`, `performance`, `setTimeout`, `setInterval`, `crypto`, any DOM global. BACKLOG 28: also `.sort()` or `.toSorted()` without a comparator (string order), `Intl`, `Symbol`, `localeCompare` and `toLocale*` (locale or identity dependent).
  - Ordering: every sort comparator ends with an entity-id tiebreak; Map and Set are fine only when insertion order is itself deterministic; never iterate object keys built from runtime data.
  - Hashing of data packs uses canonical JSON (sorted keys, LF line endings) so Windows line endings never change a hash.
  - One seeded PRNG per sim (`xoshiro128**` or `sfc32`), streams split by purpose (combat, ai, weather) so adding a feature does not shift other streams.
- **Entity storage:** structure-of-arrays in typed arrays with a free list and generation counters (`EntityId = (index | ((generation & 0x7fff) << 16)) >>> 0`, index under 65536). Components are column groups: transform, motion, health, tribe, unitKind, task/state machine, building, tree, projectile, status effects.
- **System order per tick** (each a pure function over the state):
  1. apply external commands (validated; invalid commands are dropped and logged as events)
  2. AI controllers emit commands (every N ticks, deterministic)
  3. tasks and decisions (settler job assignment, troop target selection)
  4. pathing requests (budgeted per tick)
  5. movement and collision (spatial hash on torus)
  6. combat, projectiles, spells and effects
  7. terrain ops queue (applies edits, marks dirty chunks, drowns units now under water)
  8. economy (mana income and sink distribution, wood, breeding, construction)
  9. worship, triggers, objectives, win/loss
  10. events flush, hash checkpoint if `tick % hashEvery == 0`
- **Commands:** `{tick, tribe, type, args}` plain JSON. Every player action, AI action and bot action is a Command. Replays, bots, multiplayer lockstep and save games all reuse this format.
- **Events:** sim emits an ordered event list per tick (unitDied, spellCast, buildingDone, drowned, conversion, shaperDied). Renderer and audio consume events; tests assert on them. As built (M6): `packages/audio` `AudioHooks` maps events to cues through `style.json` `audio.cues` (`cue` with `{field}` substitution, `maxPerTick` throttle, `where` filter); cues without an available asset count as silent stubs, and the debug summary reports `audio` stats. As built (M10): `AudioHooks` takes a sink and an alias table (`audio.alias`, a cue borrowing another clip); `WebAudioPlayer` (`player.ts`, browser only) plays one-shots on sfx, voice and music buses (gain is the squared master times the squared bus setting), unlocks on the first pointer or key gesture (cues before that are skipped, never queued), and crossfades looping music stems. `mix.ts` holds the pure decisions Node tests cover: `spatial` (full volume inside a quarter of the radius, linear falloff to the radius around the camera focus, wrap aware, panned by the screen-space offset; the app sets the radius to `24 + 96 * zoom`, 0 in map view) and `MusicDirector` (battle while combat events land within 24 cells in the last 15 s, tension for combat anywhere or a rival raid in the last 35 s, else calm; upgrades at once, downgrades after a 20 s hold, sim time so reproducible; the game calls it every frame, and sim time going back (a new world or a loaded save) resets it to calm). The app adds player-facing cues the sim table does not cover: button clicks, selection, move orders with the Shaper's acknowledgement, rejected commands, a throttled casting bark, the under-attack bark when the local Shaper dies, and the victory line.
- **Hash:** `sim.hash()` FNV-1a or xxhash32 over heightmap, entity columns and RNG state. Golden replays assert checkpoint hashes; the first divergent tick pinpoints a bug.
- **Snapshots:** `sim.snapshot()` returns transferable typed arrays so the sim can move to a Web Worker later without refactoring. Save game = snapshot + data pack hashes + command log tail (the app also stores the end screen match stats, `SaveGame.stats`, outside the hashed snapshot, BACKLOG 79, and the opponents' `bots` specs, BACKLOG 50: `makeBot` stamps each controller with its `botSpec`, and a load or replay rebuilds exactly those controllers). Besides the entity columns, terrain, RNG and tribes, a snapshot carries the unit system's A* paths and path queue, the terrain edits the unit step has not seen yet (`terrainDirty`) and the valid flow field goals (`flowKeys`, rebuilt on restore outside the per-tick build budget), and its `origin` (BACKLOG 35: the WorldInit without pack files, so `World.fromSnapshot(pack, snap)` needs nothing else and `World.restore` refuses a snapshot from a different world). Stretch 2 regression: without `terrainDirty`, a save taken between a terrain edit and the next unit step made the restored world re-plan every A* walker and drift from the live game (the e2e BACKLOG 76 check failed now and then at tick 221; `tools/harness/_saveprobe.mjs` checks hundreds of save points of a skirmish against the live run).

### Terrain
Torus heightmap `Int16Array(w*h)`, modulo indexing everywhere through one helper. Height scale: `heightUnitsPerWorldUnit` (default 32) in `balance.json`; one cell is one world unit horizontally. Ops: raise, lower, set, flattenToAverage, smooth, crater, ridgeLine, noiseScar, lowerTowardSea, scar. Dirty rectangles per op feed (a) chunk remesh in the renderer and (b) path-graph invalidation. Scar map `Uint16Array` holds seconds of scarring left per vertex and heals one second per sim second. As built (M1): heights live at integer vertex coordinates and `heightAt` interpolates bilinearly with wrap; a unit drowns when water at its position is deeper than `drownDepthHeightUnits`, while shallower water is impassable for pathing but survivable; every op lives in `packages/sim/src/terrain.ts` and is reachable as data through `TerrainOpSpec` (spells, buildings and the god-mode `terrainOp` command).

### Planet generator
`packages/sim/src/generator.ts`, tuned by `data/base/terrain.json`: tileable fbm value noise (integer lattice hash, no transcendental math), thresholded by histogram so `landFraction` of vertices are land, land heights normalized to the generator range with a `peakiness` curve, then terraced when the preset has `terrace` (BACKLOG 0a): each land vertex snaps to a level `step` band for the lower `flat` share of the band and ramps through the rest, and the flat share shrinks with the local pre-terrace gradient over `rampSlope`, so gentle land forms level plateaus with cliff bands while steep land keeps walkable ramps (the largest walkable component stays at its unterraced share). Hearth sites are chosen on the largest walkable component by farthest-point sampling and flattened; the seed rerolls (`seed + attempt * 7919`) when sites are too few, too close or disconnected. Trees by height band times a cluster mask, plus a grove ring around each Hearth (BACKLOG 0a, `trees.hearthGrove`: 9 to 15 cells out at density 0.25 wherever the band grows trees, so villages are ringed by forest); 6 to 10 wild people per Hearth on the same landmass. Rock outcrops (BACKLOG 0c, `terrain.rocks`) follow: `perHearth` spread by angle `distance` cells from each Hearth on its walkable component, plus `scatterPerThousandLand` anywhere on land, each on gentle land away from Hearths and other rocks; trees within `clearTreesRadius` of a rock are removed. Test maps: `flat`, `flat_with_channel`.

### Pathfinding
Cost field per cell from slope and water. Hierarchical: 16x16 cell sectors with portal graph for long routes (A* on portals), flow fields for group moves to one target, local steering and separation for crowds. Dirty terrain invalidates only touched sectors. Per-tick path budget; units waiting on a path keep their last order. Invariant tested: no unit stays "stuck" (no progress, has order) longer than 10 s in soak runs. As built (M3, ADR-004): full-grid A* with component labels and a per-tick expansion budget, flow fields for groups of `groupFlowMinUnits` or more, torus spatial hash separation, route-progress stuck detection with repath and give-up; sectors and portals deferred until a bench warns. Since M6 `astar` returns the goal directly when `lineWalkable` (1/8-cell sampling) clears the straight line, charging the line length in cells to the per-tick budget. Since M7 a goal off the walkable land (sea, cliff) is steered to and arrived at its snapped vertex (the flow goal or the path's last waypoint), and a terrain change restarts route progress for flow-field units as it already did for path units, so a longer detour is not read as stuck. Since BACKLOG 7 the same holds for a stuck repath: when A* hands back a route longer than the unit's best progress, progress restarts at the new route's length (a same-length route keeps the stuck count, so a truly stuck unit still gives up). Since BACKLOG 4 the `move` command takes an optional `formation` (`"box"` or `"line"`): for 2 to `balance.movement.formation.maxUnits` units, `packages/sim/src/formation.ts` gives each unit its own slot `spacing` cells apart around the goal, facing from the group's wrapped center to the goal, ranked front to back (trained melee troops, then settlers, Shades and others, then ranged and Chanters, the Shaper last) and sorted sideways inside a row so paths do not cross; each unit then gets its own A* order. Without the arg (all bots, AI and older replays) or for bigger groups the shared flow field is unchanged. The game sends `formation: "box"` for player moves of 2 or more units. AI controllers (`Controller` in `packages/sim/src/world.ts`, implementations in `packages/ai`) run in system step 2 and issue ordinary Commands.

### Economy (M4)
`packages/sim/src/economy.ts`: settler job state machine and per-tribe assignment (system step 3: chop, haul, flatten, build, move home; one occupant stays to breed), construction sites and dwellings with occupancy, auto-upgrade and breeding under the population cap, tree regrowth and spread, mana income by follower state into the spell and training sinks with the split slider (step 8). Tribe economy state (`TribeEco`) is part of the hash and snapshots. The economy bot (`packages/ai/src/economyBot.ts`) only places dwelling plans, choosing among the first two buildable rings around the Hearth the site with the least flattening work (`flattenWork` plus a per-ring cost); everything else is autonomy. `planBlocker` refuses a site whose pad, flattened to its target height, would be walled in (`Terrain.padConnects`: a local walkable BFS from the pad must reach 6 cells beyond it; reason "site would be walled in"), a regression from the terraced economy soak seed 1003. Stone (BACKLOG 0c): rocks are entities (`CAT.rock`) whose `stone` column holds the stone left (a site's `stone` column counts stone delivered); settlers run `toRock`, `mine` (`mineSecondsPerStone`) and `haulStone` alongside the wood jobs in `assign`, and `buildCap` holds construction to the delivered share of `stoneCost`. `stoneInReach(x, y)` asks whether a rock with stone stands on the walkable component of a point (cached per tick, `treeVersion` and terrain version); `planBlocker` refuses "no stone in reach" and a rock in the footprint ("a rock is in the way"), the economy bot's `findSpot` and the opponent's lodge and tower scores skip stone buildings without it. An emptied rock dies "quarried", a flooded one "flooded". `treeVersion` bumps on every tree or rock change, the prop layer's cache key.

### Progression (BACKLOG 0b)
`balance.progression.tiers` (data) lists follower thresholds and the buildings each tier opens; buildings not in any tier are always open. `economy.update` raises `eco.tier` (hashed, snapshotted) when the tribe's followers first reach the next threshold and emits `tierReached`; tiers never close. `EconomySystem.buildingLock(tribe, type)` returns "needs N followers" or null; `placePlan` rejects locked buildings (`locked: ...`) except in god mode, WarBot skips them, and the HUD greys locked build buttons and shows the next tier in the objectives panel. Spell unlocks by worship arrive with Shrines and Reliquaries (M9).

### Fog of war (BACKLOG 3)
`packages/sim/src/vision.ts`, ADR-011. `VisionSystem` keeps two `Uint8Array` grids per tribe over the torus at `balance.vision.cellSize` (2 map cells): `explored` (never cleared) and `visible`, recomputed every `everySeconds` (0.5 s) in step 10 just before `tick++` and once after world generation: each live unit not inside a building and each building stamps a disc of its sight (`sight[id]`, else `unitSight` or `buildingSight`). `sees(tribe, x, y)`, `seen`, `seesEntity` (own, a tribe without a Hearth, or in sight) and `seenEntity` (also ground seen before) are the only queries; tribe -1 is god mode. Off (everything seen, nothing hashed or saved, older replays keep their hashes) when `balance.vision` is missing or disabled or the `MapSpec` has `fog: false`. Commands never check it; the opponent AI filters threats, targets, clusters and Shade targets through it unless its difficulty has `mapHack`.

### Worship (M9)
`packages/sim/src/worship.ts`. A worship object is a `CAT.worship` entity plus a `Site` record in `WorshipSystem` (kind index into `buildings.worship.kinds`, tag, worshippers needed, prayer ticks, uses left, rewards, per-tribe progress). The `worship` command (`{units, site: id or tag}`) walks units to golden-angle slots on a ring inside `worship.radius`; they switch from `TASK.toWorship` to `TASK.worship` on arrival. Step 9 counts each tribe's idle, unengaged worshippers per site; speed is 1 at full count times `missingWorshipperSpeedFactor` per missing worshipper (a `shaperOnly` totem counts only the Shaper, as a full count). Progress decays by `decayPerSecond` of a full prayer while a tribe has nobody praying. The first tribe (by index) to finish gets the rewards via `applyReward` (charges, unlockSpell, unlockBuilding, spell cast from the site toward `at`, spawn, message; level triggers share it), everyone praying there stands down, and a site out of uses sinks if its kind `sinks`. Rewards may queue terrain ops, so step 9 flushes the terrain queue again. Granted buildings bypass `buildingLock`; one-shot charges let a locked spell be cast. Plans may not overlap a site's ring. Sites and grants hash and snapshot only when present, so worlds without them keep pre-M9 hashes. Events: `worshipComplete`, `siteSank`, `worshipFailed`, `rewardCharges`, `spellUnlocked`, `buildingUnlocked`, `rewardSpawn`, `levelMessage`.

### Campaign levels (M9)
`packages/sim/src/level.ts`, ADR-009. `createLevelWorld({def, carry}, pack, hash, makeAi)` builds a world from a `LevelDef` (`data/levels/<id>.json`): `levelMap(def)` (flat generator plus `paint` shapes, applied in the generator so restore regenerates the same base), per-level spell unlocks (start charges kept only for opened spells), the campaign carry for the player (spells unlocked, buildings granted), `applySetup` (worship objects with `site` specs) and an OpponentAI per AI tribe. `LevelRuntime` (`world.level`, null in skirmish) runs in step 9 after worship: triggers fire once (time, a site completed, an objective done; rewards anchor at the site or the player's Hearth), objectives latch done, then the outcome: won when every objective is done, else lost on elimination, `timeLimit`, `siteLost` or `hearthLost`. Events `triggerFired`, `objectiveComplete`, `levelWon`, `levelLost`. `level.allowed` limits buildings (`buildingLock`: "not available in this level"; grants bypass it). BACKLOG 83: a level tribe's `maxTroops` caps its training: `combat.troopCount` counts trained troops plus settlers walking to or in training, the `train` command is trimmed to the room left and refused at the cap ("this level caps your troops"), and the opponent AI stops scoring training there (Hold the Line: the rival is capped at 8, so the second wave of 6 raiders decides it; an idle player loses, the turtle defender wins). Hashed and snapshotted only when a level is present. ADR-015 (BACKLOG 9): the app's campaign progress keeps `learned` (spells each won level taught in play) and carries them into later levels with the static `unlocks`; the level select is a route map (`menus.tsx` Campaign). A win beats a loss on the same tick (objectives are checked first). S2 block H: a level may name `rules` (a `balance.victory` variant; its holdSites and kingOfHill count the level's own worship sites) with the `victory` objective, met when the player wins them, while a rival winning them loses the level as `outplayed`; and `forge: true` opens it with a Forge (level timers and time triggers read `playTick`, so they start at its end). `levelWorldInit` builds the WorldInit for fresh and restored level worlds alike, so saves keep rules and Forge.

### Vehicles (BACKLOG 10)
`packages/sim/src/vehicles.ts`, ADR-016. Unit types with a `vehicle` block move on their own nav layer (`UnitSystem.pfs[NAV.*]`, `pathing.ts` modes `land`, `water`, `air`); riders sit inside like a garrison (`inside`, task `ride`), boarding (`toBoard`) and unloading (`unload`) are tasks driven in system step 5b after units. Buildings with `makes` produce vehicles; `placement: "shore"` is checked in `economy.planBlocker`. The renderer floats boats on the sea surface and lifts balloons by `BALLOON_LIFT`; the game maps right clicks to `board` and `unload` (`troops.ts vehicleCommand`). Boarding retry period and tries, the unload reach and the shore reach are `balance.vehicles` (code defaults when absent). Riders unload in a 3 x 3 fan around the landing vertex; riders past nine repeat it with a small nudge so none lands past the cell edge. The opponent AI contests sites on other landmasses by ferry: `contestTarget` prefers home sites, an off-home site sends the wave to a boat with a goal (`OpponentAI.goals`, saved) so the boat sails to the shore nearest that site, and a landed wave goes for a contested site on that landmass it does not hold before the enemy Hearth.

### Forge mode (BACKLOG 11)
`packages/sim/src/forge.ts`, ADR-017. `WorldInit.forge` builds `ForgeRuntime` (`world.forge`, null otherwise) from `balance.forge`. While it runs, `step` runs commands, controllers, terrain ops with the drowning check, the Forge and vision only, then returns; commands outside `FORGE_COMMANDS` are rejected. `forgeOp` strokes (raise, lower, flatten, smooth) are free inside the tribe's ring around its own Hearth (`ForgeRuntime.blocker`), `forgeReady` ends it early once every living tribe is ready, the timer ends it otherwise. `World.playTick` counts from its end and drives match clocks (Last Stand, level timers, the AI's minute). Hashed, saved and restored only when present. The opponent AI forges by its personality `forge` plan (moat, wall, flatten).

BACKLOG 14b: match weather. `WorldInit.weather` ("clear" or "rain", from skirmish params, a level's `weather` or a scenario's) sets `world.weather` and `world.speedMult` (`balance.weather.rain.speedMult` in rain, else 1); the unit move step scales every unit's speed by it. Hashed only in rain, so clear worlds and older replays keep their hashes. The app shows rain for a rainy match whatever the Weather setting says (`applyQuality` after `setWorld`).

### Skirmish victory rules (BACKLOG 13)
`packages/sim/src/rules.ts`, ADR-014. `WorldInit.rules` names a variant from `balance.victory` and builds `RulesRuntime` (`world.rules`, null without `WorldInit.rules`: old saves, and levels that name no `rules`), run in step 9 after worship and before the level (a level with rules reads the same tick's winner). Conquest (one tribe left) applies under every variant; holdSites (alone at every site for an unbroken run of `seconds`), kingOfHill (strictly most people at the first site for `seconds` in all; a tie scores nobody) and lastStand (most followers at `minutes`) read presence within `controlRadius` once a second, on site ground captured at the first step. The decision is `winner`, `why` and the `matchWon` event; `game.ts checkEnd` maps it to the end screen. The opponent AI's `contest` action sends idle troops to the nearest site it does not hold. Hashed and snapshotted only when rules are present.

## 4. Data packs (`data/`, `packages/data`)

- Files: `units.json, buildings.json, spells.json, effects.json, ai_personalities.json, balance.json, terrain.json, style.json`. Campaign levels live in `data/levels/*.json` (M9): validated against the merged pack by `validateLevel`, not part of the pack hash or the mod merge; a campaign save embeds its level definition instead. `data/achievements.json` (BACKLOG 21, ADR-019) is validated the same way by `validateAchievements` and is not hashed either; the app reads it for achievements and the Records screen. UI string tables live in `data/strings/<locale>.json` (BACKLOG 22, ADR-020), looked up by key with `t()` from `@hearthfall/ui` and checked by the strings guard.
- Every file validated by a zod schema; JSON Schema exported to `data/schema/` and a human reference generated to `docs/DATA.md` by `npm run data:docs`.
- Packs merge by `id`: `base` then any `mods/<name>` pack in load order; a mod can add, override fields, or remove (`"$remove": true`). Each pack has a manifest with version and a content hash (part of replays and saves). As built (BACKLOG 18, ADR-021): `applyMods` (`packages/data/src/mods.ts`) deep merges mod patches onto the raw base files before validation and reports conflicts by path; Node loads mods with `loadBasePack(mods)` (`npm run mods`, `soak --mods`), the app with `?mods=a,b`; the merged pack has its own hash. Modder guide: `mods/README.md`.
- Hot reload in dev: editing a data file reloads it in the running game (dev only, not deterministic).
- Rule: if a value is a number that a designer might tune, it lives in data, not code.

## 5. AI (`packages/ai`)

Controllers implement `decide(view: SimView, rng) -> Command[]` and run inside the sim step at their own cadence, so they are deterministic and replays need no AI commands recorded. Opponent AI = utility scoring over considerations declared in `ai_personalities.json` (economy target, army mix, aggression curve, spell preferences, scouting). Test bots reuse the same framework with scripted personalities (rusher, turtle, spell spammer, random legal). An **external** controller (human, the optional Decisions move-picker) is recorded into the command log because it is not deterministic.

As built (M6): `packages/ai` registers controllers by type (`wander`, `economy`, `war`). The WarBot wraps the economy bot (its public `findSpot` places lodges and towers too) and issues only ordinary commands (placePlan, train, setRally, move with `attack`). The movement layer's `orderGaveUp` event carries `reachable` and `chase` so harnesses can tell a stuck unit from a chase combat abandons.

As built (M7): `OpponentAI` (`packages/ai/src/opponent.ts`, type `opponent`, options `{personality, difficulty}`) is called every tick by World and decides once per period: `round(reactionSeconds * tickHz)` ticks of its difficulty (easy 6 s, normal 3 s, hard 1.5 s, brutal 1 s), on the tick where `tick % period` equals its `offset`; an explicit `every` overrides the period for tests. BACKLOG 6: a difficulty's `resourceMultiplier` reaches the sim as a `handicap` command (`args.mult` 0.25 to 4) that sets `eco.incomeMult` on the AI's own tribe; `updateMana` scales the tribe's income by it (hashed only when not 1). Only a tribe with an attached controller (or god mode naming `args.tribe`) may issue it, so a player cannot hand themselves one. Each decision runs the economy bot's dwelling upkeep, takes a census (troops by type, idle troops, lodges, towers, threats within 14 cells of the Hearth, enemy Hearths nearest first), scores nine actions (protectShaper, defend, scout, buildLodge, buildTower, garrison, train, attack, cast) from the personality numbers, adds `decisionNoise` from the `ai` rng stream, and runs the best ones scoring at least 0.5 (at most three). Spell targeting reads each spell's `aiTarget` (units, buildings, wild, bridge, ownFighting, ownMarching, none) in `spells.json`, so new spells need no AI code; ownFighting (Ward) aims at a cluster of at least 3 of the AI's own trained troops that have an attack target, ownMarching (Veil) at a cluster still under a move order. Auto-charge setup runs every decision (BACKLOG 1) so spells unlocked mid-match at worship sites start charging. Waves hold for a second troop type while two lodges stand (3 minute grace after `firstAttackMinute`) and a healthy Shaper follows them, stopping short of the target so her spells reach the fight. With no walkable route to any enemy Hearth the Shaper walks to the shore on the line toward it and raises land across (terrain attack). BACKLOG 7: a tribe whose Hearth fell is listed through its visible Shaper (it lives while she does), so waves hunt her; once any wave finds no walkable route, bridge spells (`aiTarget` bridge) join the charged prefs even for personalities that do not list them; a hunted Shaper out of reach on foot (a cliff pocket) draws our Shaper to the nearest cell of our landmass within 10 cells, and spells whose `damageRadius` has `canKill` value an enemy Shaper +2, so a lone one is worth a Lightning. BACKLOG 64: `pickCast` values every castable preferred spell at its best target (cluster score times 1 plus its kill power, the summed `damageRadius` damage over a Warden's 2600 hp capped at 1, times 1 minus 0.06 per preference rank) and casts the best, instead of the first castable preference; a personality with `towerFromPopShare` (turtle 0.5) plans no tower before that share of its `economyTargetPop` unless the Hearth is threatened. Controller-side `stats` (actions, casts by spell, waves, mixed waves, bridges) feed soak reports and are never hashed. Test bots (`testBots.ts`, ADR-007): `rusher` and `turtleBot` are OpponentAI presets in code, `spellSpammer` auto-charges and casts every spell at random enemies, `randomLegal` fuzzes the whole Command API.

Lodge payments (BACKLOG 7): each lodge trains one trainee at a time; the training-sink payments of a tick wait until every lodge is visited and are paid oldest trainee first per tribe (arrival tick in `timer`, then building index), and an unaffordable trainee blocks younger ones. In plain index order a cheap lodge with a full queue took every payment and a dearer one never trained (the AI raised only Wardens). A building destroyed on sunken land drowns the occupants it lets out at once (its kill can come after the tick's drowning pass).

Chant interrupts (BACKLOG 7): `World.damage` breaks a running chant on any non-melee hit, and on a melee swing too when the Chanter's `convert.interruptedBy` lists `meleeDamage`; `convert.entrancedFreeze` (false in live data) holds every enemy in the radius while the channel runs. Since BACKLOG 65 a Chanter with `convert.breakDamage` keeps channelling through ranged hits until the ranged damage taken since the chant began (kept in the unit's otherwise unused `progress2` column, so the entity layout and golden hashes are unchanged) reaches `breakDamage`, and while it channels a ranged knockback (`knockUnit(..., hit = true)`, as the Firecaller fireball passes) does not move it; melee hits still follow `interruptedBy`. `tools/harness/triangle-probe.mjs --seeds N --set unit.path=value` prints the 10 v 10 triangle, the 6 v 10 probes and the mixed mirror for a data override without editing files.

Shades (BACKLOG 2): combat kind `saboteur` (units with a `sabotage` block). `combat.disguised(i)` is true while the `reveal` column is 0; `validTarget` and the attack command skip disguised units (as with Veil) and the Wraith, AI census, threats and spell targeting ignore them. A Shade's strike starts a channel in the `chant` column (`sabotageBegun`, `sabotageStep`, `sabotageBroken`, `sabotaged`); `detect()` runs every 4 ticks against the `detectors` listed in data (`shadeRevealed`). Buildings reuse the `burn` column for fire, ticked in `updateEffects` and credited to `lastHit`. `EntityStore.alloc` resets every status column (veil, ward, beguile, home, stone, reveal): reused slots used to inherit statuses (`slotReuse.test.ts`). The sneaky personality's optional `shades: {count, fromMinute}` adds the `buildDen`, `trainShade` and `sabotage` actions (scored only when present, so other personalities draw the same noise); Shades stay out of waves, go for the nearest finished building of a scouted enemy away from its detectors, and scout an unscouted start site while they have none.

Reachability (M7 regressions): combat `acquire` skips targets out of reach on another walkable component and drops a target that became unreachable before issuing a fresh chase path; economy assignment only sends settlers to sites and homes on their own component. Both came from AI soaks where quake and flatten cliffs split a base. BACKLOG 48 (islands and continents economy soaks): a job with no worker on its component skips to the next job instead of ending the tribe's pass (only an empty worker pool ends it), and a settler with no home on its component no longer stops the others moving in; the economy bot only plans dwellings on the Hearth's component (`EconomySystem.compAt`), cancels a plan that later terrain changes cut off (`cancelPlan`, so it stops holding the open plan limit), and scans rings out to 32 cells before giving up. BACKLOG 49: `EconomySystem.woodInReach(x, y)` (a tree, stumps included, on the walkable component, cached like `stoneInReach`); the bot plans no wooden building when neither a tree nor one of its settlers carrying wood is on the Hearth's landmass, and cancels a plan still short of wood once both are gone. The sim itself does not refuse such plans (players may plan there; many tests and levels do on treeless maps).

## 6. Spells and effects as composition

A spell in data is a list of effect primitives with parameters:

`damageRadius, damageBuildingsRadius, knockback, terrainOp, convertRadius, statusApply (ward, veil, beguiled, burning, panic, entranced), spawnEntity, projectile, projectileStorm, areaOverTime, moverPath (whirlwind), summon (wraith), scar, lavaFlow`.

Example (illustrative): Volcano = `terrainOp(crater cone up) + areaOverTime(lava damage) + scar + spawnEntity(lavaRocks)`. New spells should be pure data. If a new spell needs a new primitive, add the primitive with tests, never a one-off spell class.

As built (M5): `packages/sim/src/effects.ts` registers damageRadius (Shapers only die to effects whose `canKill` lists them), knockback (displacement that ignores walkability, so water and cliffs kill), convertRadius (capped by free housing), statusApply (panic, burning), terrainOp (ridgeLine from the caster, flattenToAverage, noiseScar, crater, lowerTowardSea, raise, lower; an optional `leadInSeconds` holds the op in an `FX.leadIn` effect entity that applies it when its timer runs out, emitting `terrainLeadIn` at the cast and `terrainMoved` when the land moves, BACKLOG 36), damageBuildingsRadius, scar, areaOverTime (persistent effect entities) and spawnEntity (sub-entities from `spells.json` `entities`, such as lava rocks). `packages/sim/src/spells.ts` owns the cast command (walks into range, a `castSeconds` window during which `cancelCast` refunds), resolution, Shaper death, respawn at the Hearth, charge steal and elimination.

As built (BACKLOG 1, the eight non-v1 spells): statusApply also does `veil`, `ward` (both `targets: "own"`) and `beguiled`, kept in the entity columns `veil`, `ward`, `beguile` (ticks left) and `home` (the tribe a beguiled unit returns to). Veil: other tribes' units, towers, Wraiths and the AI ignore the unit until it attacks. Ward: no damage and no knockback (drowning and Mire still kill); spells in its `poppedBy` strip it first (`wardPopped`). Beguiled: the unit converts in place for `seconds`, then returns (or turns wild if its tribe is gone); all of a tribe's beguiled units return when its Shaper dies. Persistent effect entities share `FX` kinds in `effects.ts` and read their numbers back from the spell each tick: `erode` (lowerTowardSea with `seconds`: one step per second), `storm` (projectileStorm: impacts spread evenly over its time, each hitting units and buildings within `impactRadius`, event `meteor`), `mover` (moverPath: a wandering vortex that flings units, event `flung`, and wears buildings down by `buildingDamagePctPerSecond`), `trap` (Mire: kills the first `kills` non-caster enemy units in its radius, event `mired`) and `wraith` (summon: flies to the nearest huntable enemy unit, never a caster, veiled or warded one, and kills one every `killSeconds`, event `wraithKill`). Scenarios: `scenarios/spell_{veil,ward,beguile,whirlwind,mire,erode,firerain,wraith}_*.json`. A unit converted while garrisoned steps out first (`convertUnit` calls `leave`), so a beguiled unit never sits in a building of the wrong tribe. Skirmish unlock path (ADR-010): `WorshipSystem.placeSkirmishSites` puts up to `balance.skirmishWorship.maxSites` Reliquaries on generated maps (populate on, no level), at the midpoint of each pair of Hearths and its opposite on the wrapped planet, moved to the nearest dry cell clear of every Hearth; sites take `sites[]` entries in turn (veil, ward, beguile, whirlwind, then mire, erode, firerain, wraith). Renderer: `UnitLayer.viewTribe` and `Vfx.viewTribe` (0, the local player) hide other tribes' veiled units and their halos; own units show a status halo (ward gold, beguile pink, veil pale); effect entities draw by `FX` kind (whirlwind funnel, wraith core and motes, firerain edge ring, mire and erode pools; BACKLOG 0a: the erupting volcano cone, not its lava rocks, draws a leaning column of normal-blended ash puffs about 13 world units tall with embers at the vent, so it reads at mid zoom).

## 7. Renderer (`packages/render`)

- `Renderer` interface (`init, setSnapshot, setCamera, render, captureReady, dispose`) so WebGPU or another engine can replace it.
- **Terrain:** 32x32 cell chunks as BufferGeometry with vertex colors from height band, slope and scar; only dirty chunks remesh. Water is one shader plane at sea level plus shoreline foam from a depth texture or vertex attribute.
- **Curved world:** a shared material factory patches every world material (terrain, water, units, props, VFX) in `onBeforeCompile`, replacing the `project_vertex` chunk so the bend happens in **world space after the instance matrix**: `worldPos.y -= k * dist2(worldPos.xz, focus)`. Shadow casters get a matching `customDepthMaterial`. `k` grows with zoom so close-up is nearly flat and globe view reads as a small planet (a later option: true angular sphere mapping for the globe view). Map view sets `k = 0` and draws through `Renderer.mapCam`, an orthographic top-down camera fitted to the world square at any aspect (BACKLOG 37/40); `Renderer.view` is the camera in use for drawing and picking. The map draw focus snaps to a chunk corner so the chunks tile the square exactly, and `mapFrame` masks past the world edge and draws the grid (`style.json render.mapFrame`).
- **Culling:** bent geometry no longer matches its bounds, so terrain chunks use `frustumCulled = false` (or bounds expanded by the bend at their distance); units are culled on the CPU by distance from the focus.
- **Wrapping:** each terrain chunk renders at the wrapped copy nearest the camera focus; units and props wrap by their **instance origin** (never per vertex). Fog fades everything to the sky color before half the world width minus one chunk, so the nearest-copy jump is never visible, even in globe view. Seam shots live in the visual suite.
- **Water:** a tessellated grid (not a 2-triangle plane, which cannot bend) at sea level, with shoreline foam from a depth attribute.
- **Spell previews and range rings:** terrain shader uniforms (center, radius, shape, color), not decals, so they follow the bent surface exactly.
- **Units and props:** `InstancedMesh` per (kind, LOD); only changed instance matrices update. Procedural placeholder meshes from the `style.json` palette until glTF assets exist; the loader swaps them in by manifest id with automatic fallback. As built (M10): `models.ts` parses each GLB once (`loadModels` never throws; failures are reported and keep the placeholder), splits its triangles by the azure tribe marker into a body part (vertex colors) and a white tint part that the layer paints per instance, adds a banner to buildings with almost no marker, and trims tree root discs. `ThreeRenderer.loadModels(urls)` rebuilds the tree, building, unit and worship layers when they arrive; `modelStatus()` reports pending, loaded, failed and drawn ids. Models use their authored size (scale 1; worship sites 1.5, trees 0.72), except building models, which draw at `style.render.buildingScale` (1.3 since BACKLOG 0a, matching the units' readability scale so villages read as villages; `(scale - 1)` times the largest footprint must stay within `buildingGapCells`, a render test checks it); placeholders keep their footprint scaling. M11 readability (rings tilt to the ground slope and lift over creases since BACKLOG 94, `UnitLayer.groundFit`, cached on a half-cell grid per terrain version by `groundFitCached` for the render budget): every tribe unit stands on a small ring in its tribe color (an annulus, so crimson never reads as a blood pool; wild people get none), the Shaper draws 1.2 times larger on a 1.5 times ring, and real tree models get a lighter, greener instance tint so forests do not read as dark blobs from afar. BACKLOG 0a: a procedural tall three-tier conifer (`tallPineGeometry`, about 2.1 units, own scale, darker tint) joins the GLB tree set and draws `PINE_SHARE` (0.7) of the trees, so forests read as pine belts (look v2). BACKLOG 0c: the same layer draws rock outcrops from the `prop.rock_a/b/c` GLBs (else a faceted boulder placeholder), each scaled to `ROCK_WIDTH` wide and at most `ROCK_HEIGHT` tall (a tall model would read as a monolith), shrinking to 55 percent as its stone runs out. Worship sites (M9, `worshipLayer.ts`) are placeholder stone meshes per kind (shrine ring, reliquary obelisk, totem pole) whose crown takes the color of the tribe leading the prayer, else the last tribe to finish it, and goes grey when spent.
- **Picking:** CPU raymarch against the bent heightfield (apply the same bend function), so clicks and spell previews are accurate on the curve. Unit picking uses the spatial hash near the hit point. `pickGround(px, py)` marches against flat sea level instead and returns unwrapped coordinates; the minimap uses it for the camera footprint, since grazing rays that hit hills would make the outline zigzag. The footprint is clipped to the terrain fade radius (`clipFootprint`, BACKLOG 80), so it never folds over the wrap on small maps.
- **Unit animation (BACKLOG 5, ADR-012):** units bend procedurally in the vertex shader. `unitAnim.ts` holds the clip choice from sim state (`unitClip`), pure poses (`unitPose`, `deathPose`), the per-vertex rig attribute (`rigGeometry`: model height and x share) and the GLSL chunk; `bendMaterial(mat, u, undefined, true)` injects it after `begin_vertex` (cache key `hf-bend-anim`), and meshes without `aRig` are untouched. `UnitLayer` writes one `instanceAnim` vec4 per instance per frame (shared by a kind's body and detail meshes) and draws a 1.2 s toppling ghost for every `killed` or `drowned` unit event it consumes. `__game.setAnimProbe(on)` plays clip (slot mod 8) on every unit for the pose gallery shot (render only).
- **Fog of war (BACKLOG 3):** `ThreeRenderer.syncFog` uploads the viewer's grids (`viewTribe`) as a `RedFormat` `DataTexture` (255 visible, 128 explored, 0 unexplored; linear filter, repeat wrap) only when `vision.version` changes, into the shared bend uniforms (`uFogTex`, `uFogSize`, `uFogOn`, `uFogDark`), so every bent material darkens by the same rule in `BEND_FRAGMENT_FADE` (unexplored to 0.16, explored to 0.55). The unit layer and status halos skip entities the viewer does not see; the building layer skips buildings whose ground was never seen. `revealFog` (URL `reveal=1`, `__game.setReveal(on)`) draws everything, render only.
- **Post:** fog to horizon, ACES tone mapping, light bloom for spells, optional SSAO later. All toggles in a quality preset.
- **Retro pass and tilt-shift (ADR-005, ADR-013):** `retro.ts` renders the scene into a low-res target (with a `DepthTexture`) and one fullscreen quad tone maps, lifts and quantizes it; the optional miniature focus band blurs outside the camera focus (`style.json render.tiltShift`, order `post` = average of quantized taps). `setTiltShift(mode)` and `setPixelScale(n)` switch it at runtime (Settings Miniature focus, URL `tiltshift`, `pixel`); map view turns it off.
- **Painted water (BACKLOG 14a-2):** the renderer keeps a per-cell depth `DataTexture` (sea minus height, float, linear filter, repeat wrap for the torus) and re-uploads it with every terrain remesh; the water shader samples it per fragment for smooth shallows, a crisp wobbling shore foam line and a fainter ring that drifts offshore (`style.json render.water`). Without the texture it falls back to the per-vertex depth.
- **Trees (BACKLOG 14a-3):** `props.ts` TreeLayer draws two procedural round clump variants (merged faceted blobs in yellow-greens), the tall conifer and the GLB tree models; `style.json render.trees` sets the clump share by altitude band (lowlands mostly clumps, heights mostly conifers), the GLB share of the rest and a per-instance warm or cool hue jitter.
- **Terrain bands and model alias (BACKLOG 14a-4):** `style.json render.terrainBands` moves snow down to `snowStart`..`snowFull` (brightened and cooled by `snowBright`) and paints the middle stratum of earth cliffs toward sand. `render.modelAlias` maps a model id to a replacement file id (`aliasModels` in `models.ts`, applied before loading; `apps/game/src/icons.ts` swaps the icon the same way), so the look v3 thatched dwellings (`building.dwelling_*_v3.glb`) replace the originals without overwriting them; removing an alias restores the old model.
- **Lighting presets and weather (BACKLOG 14):** `weather.ts` `resolveLighting` turns a preset name (`style.json lightingPresets`, default `lightingDefault`) and a weather name into one look: key light color, intensity and direction, hemisphere sky and ambient scale, hearth glow scale, rim haze, and for rain a dimming factor plus `RainLayer` streaks that fall in a vertex shader around the camera focus. The unlit water takes a `waterTint` relative to the default preset (white under golden). `Renderer.setLighting(preset, weather)` applies it at runtime; the Weather setting is visual only, while a rainy match (BACKLOG 14b, `world.weather`) also slows units in the sim and always shows rain.
- Budgets (on Stewart's RTX desktop): 60 fps at 1440p with 1000 visible units and 2000 total; renderer CPU under 6 ms per frame.

The panel is `packages/ui/src/editor.tsx` fed by `editorBridge.ts`.

Agents read `getSummary()` and headless harness output first. Screenshots are the last resort.

## 10. Extension points (design for weeks of growth)

New unit, building, spell, AI personality, level, terrain biome, or mod pack: data only. New effect primitive, new system, new renderer backend, new controller type: code with a test, registered through a registry, never a switch statement buried in a system. Multiplayer later: lockstep over WebSocket using the same Command stream and per-tick hash comparison for desync detection.
